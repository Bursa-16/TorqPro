# TorqPro AI v3.0.0 — Release Notes

**Status:** Stable, 2026-08-13.
**Baseline:** `v3.0.0-rc.1` (`3c9efedf58b4f07cbd65bca7b50f2ac039209cf3`).
**Previous release:** `v3.0.0-rc.1` (Performance, Security &
Documentation).
**Next milestone:** none defined yet -- future work will be scoped
separately.

This is a **release-metadata/version transition only**: no
engineering logic, AI/reasoning behavior, API contract, or
security/performance control introduced in Beta.1/Beta.2/rc.1 changed
in this phase. `VERSION`, `tests/test_version_centralization.py`,
`README.md`, `docs/314_Roadmap.md`, and `docs/CHANGELOG.md`'s
`v3.0.0` entry are the only substantive changes, plus a narrow
`.gitignore` addition so running the opt-in benchmark suite no longer
dirties the working tree.

Full detail on everything delivered across the v3 cycle is in
`docs/CHANGELOG.md` (each phase has its own dated entry). This
document summarizes the cumulative result by category, as of stable.

## Deterministic Engineering (Alpha–Beta.1)

- VDI 2230 threaded/bolted-joint analysis
  (`backend/vdi2230_core`/`backend/calculation_engine`/
  `backend/engineering_core`/`backend/standards`) is the sole source
  of truth for every numeric engineering result.
- **Torque Recommendation Engine** (`backend/torque_recommendation/`,
  `v3.0.0-beta.1`): deterministic, offline-capable, with fail-closed
  status/confidence classification and its own persisted audit trail.
- No AI/reasoning component can modify, override, or recompute a
  deterministic engineering value -- enforced structurally (AST-based
  one-way dependency guard,
  `tests/ai/test_dependency_direction.py`) as well as by test, not by
  convention alone.

## AI Layer (Alpha.1–Alpha.6, Beta.2)

- Question Bank-grounded retrieval, an evidence-sufficiency checker
  (`backend/ai_gateway/evidence_checker.py`, PASS/WARN/FAIL), and a
  result-label vocabulary
  (CALCULATED/VALIDATED/ESTIMATED/RECOMMENDED).
- A provider-abstraction registry (`backend/ai_gateway/providers/`)
  with an always-available deterministic/offline provider; any real
  network-calling provider is opt-in and never required for
  deterministic engineering or reasoning output to function.
- **Engineering Reasoning Engine** (`backend/ai_gateway/reasoning/`,
  `v3.0.0-beta.2`): explains an already-computed Torque
  Recommendation result by `trace_id`, never re-running the
  deterministic engine. A closed, three-state outcome vocabulary
  (`SUPPORTED`/`UNSUPPORTED`/`INSUFFICIENT_EVIDENCE`; no invented
  numeric confidence score) with a structurally separate, optional,
  fail-soft AI-wording layer -- an unavailable or failing AI provider
  never affects the deterministic reasoning result or HTTP status.
- A persistent, hash-only (raw prompt/response text is never stored)
  audit trail (`ai_audit_records`), reused unchanged across
  Beta.2/rc.1 rather than duplicated.

## Security Hardening (rc.1)

- `TORQPRO_ALLOWED_HOSTS` enforced via Starlette's
  `TrustedHostMiddleware`.
- `TORQPRO_ENV=production` disables `/docs`, `/redoc`, and
  `/openapi.json`.
- A real cross-user authorization gap
  (`POST /api/calculations` accepting any `project_id` without an
  ownership check) found and fixed.
- Centralized, opt-in (`TORQPRO_API_RATE_LIMIT`, default off)
  per-session API rate limiting.
- Content-Security-Policy on every response; Strict-Transport-Security
  in production.
- Four previously exception-leaking endpoints now return a fixed,
  generic client-facing message while still logging full detail
  server-side.
- `pip-audit` wired into CI as a dedicated security-scan step.

## Performance Validation (rc.1)

- An opt-in benchmark suite (`tests/performance/`,
  `TORQPRO_RUN_PERFORMANCE_TESTS=1`) covering every critical request
  path -- skipped by default so the normal suite is unaffected.
- SQLite `journal_mode=WAL` and `busy_timeout=5000` tuning.
- Concurrent read/write smoke testing: zero errors, zero lost or
  duplicated writes under simultaneous requests.

## Public / OEM Sanitization

No proprietary/OEM-specific standard name or identifier is exposed in
any Torque Recommendation, Engineering Reasoning, or audit output --
verified by dedicated regression tests carried through Beta.1,
Beta.2, and rc.1, and re-confirmed at stable.

- Full test suite: **3371 passed, 13 skipped** (the opt-in benchmark

  Deferred / Hygiene" below).

## Known Deferred Items (post-v3.0)

Unchanged from rc.1's own deferral list -- none of these are
release-blocking:

- A strict, nonce/hash-based Content-Security-Policy (would require
  restructuring `frontend/index.html`'s single inline `<script>`
  block and roughly 220 inline `style="..."` attributes into external
  files first).
- A broad `sync`→`async` route rewrite (no evidence of threadpool
  saturation found at the concurrency levels exercised in rc.1's
  smoke tests).
- A JSON-to-SQLite persistence redesign for the Question Bank and
  washer-resolution stores (not a present-scale problem at measured
  and synthetic larger scale).
- A large connection-count or query-shape refactor beyond the
  specific, measured `journal_mode` fix already made.
- Any hard, cross-machine performance regression threshold (rc.1's
  benchmark baseline is local and informational, not a checked-in
  target).
- No new major roadmap phase is defined as of this release; future
  work will be scoped separately.

## Hygiene

Running the opt-in benchmark suite generates
`tests/performance/baseline_results.json`, an untracked runtime
artifact. A narrow `.gitignore` entry for this exact path was added
at stable so benchmark execution no longer dirties the working tree
-- no broader path was ignored.
